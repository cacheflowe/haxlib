# Harness Support

This document explains how to author skills, prompts, and MCP servers for different AI Harnesses, and how to verify they're working correctly in each supported surface: **Claude Code**, **GitHub Copilot**, **Codex**, and **Gemini CLI**.

## Skills

A skill is a directory containing a `SKILL.md` file with `name` and `description` frontmatter. Optional subdirectories (`scripts/`, `references/`, `assets/`) can be added but are not required.

```

Use a slug-style `name` that matches the folder name, such as `code-reviewer` for `.agents/skills/code-reviewer/SKILL.md`. This keeps explicit invocation (`$code-reviewer`) and selector display consistent across Codex surfaces.
my-skill/
  SKILL.md        ← required: name + description frontmatter + instructions
  scripts/        ← optional
  references/     ← optional
```

**Description quality matters.** All skill descriptions are included in context so the agent can choose the right skill. Write descriptions that explain exactly when the skill *should* and *should not* trigger — front-load the key use case and trigger words. Codex caps the total skills list at ~8,000 characters and shortens descriptions when over budget, so brevity counts.

### Claude Code

Skills location (project): `.claude/skills/<name>/SKILL.md`
Skills location (user, all projects): `~/.claude/skills/<name>/SKILL.md`

Invoke: type `/` to list skills and slash commands.

Docs: https://docs.anthropic.com/en/docs/claude-code/skills

### Codex

Skills location (repo root): `.agents/skills/<name>/SKILL.md`
Skills location (user, all repos): `~/.agents/skills/<name>/SKILL.md`

Invoke: type `/skills` to list, or `$skill-name` to mention a skill directly.

Codex also supports implicit invocation — if your task description matches a skill's description, Codex will activate it automatically.

> **Note:** `.agents/skills/` is generated by the sync script and gitignored. Run `node .ai/scripts/sync.js` after cloning to create it.
> The Codex target writes real generated `SKILL.md` files instead of file symlinks so Codex CLI and IDE skill selectors can reliably discover them. Keep editing the canonical `.ai/skills/*.md` and `.ai/prompts/*.md` sources.

Docs: https://developers.openai.com/codex/skills

### GitHub Copilot

Skills location (project): `.github/skills/<name>/SKILL.md`
Skills location (user, all projects): `~/.copilot/skills/<name>/SKILL.md`

Docs: https://docs.github.com/en/copilot/concepts/agents/about-agent-skills

### Gemini CLI

Skills location: `.agents/skills/<name>/SKILL.md`

## Prompts / Slash Commands

Prompts are slash commands — short instructions invoked explicitly via `/command-name`.

### Claude Code

Location: `.claude/skills/<name>/SKILL.md` (same directory as skills — `.claude/commands/` is deprecated)

Invoke: type `/` to list available skills and commands.

### GitHub Copilot

Location: `.github/prompts/<name>.prompt.md`

Docs: https://code.visualstudio.com/docs/agent-customization/prompt-files

### Gemini CLI

Location (project): `.gemini/commands/<name>.toml`
Location (user, all projects): `~/.gemini/commands/<name>.toml`

Format: TOML with a required `prompt` field and optional `description`. Subdirectories namespace commands with `:` (e.g. `.gemini/commands/refactor/pure.toml` → `/refactor:pure`).

```toml
# ai-sync-generated

description = "One-line summary shown in /help"
prompt = """
Body of the prompt sent to the model.
"""
```

**This harness writes generated commands to `.gemini/commands/run/<name>.toml`, invoked as `/run:<name>`.** The `run/` namespace is intentional: Gemini also auto-discovers `.agents/skills/<name>/SKILL.md` as activatable skills (invoked via `/skill <name>`), and putting commands at the top level would collide — Gemini would auto-rename both sides to `/workspace.<name>` and `/<name>1`. The namespace makes the two paths explicit:

- `/skill <name>` → loads `.agents/skills/<name>/SKILL.md` as context (activate)
- `/run:<name>` → executes `.gemini/commands/run/<name>.toml` immediately (one-shot)

**Prefer `/run:<name>` for one-shot prompts.** Both paths reach the same source file, but `/skill <name>` activates the entire SKILL.md as persistent context (more tokens, lingers across turns), while `/run:<name>` just sends the prompt body once and exits. For action-oriented prompts (`/run:update-docs`, `/run:deploy-checklist`), `/run:` is cheaper and clearer. Reserve `/skill` for cases where you actually want the instructions to stay loaded for follow-up turns.

The sync script converts each `.ai/prompts/<name>.md` to `.gemini/commands/run/<name>.toml`: YAML `description` becomes TOML `description`, and the markdown body becomes the `prompt` field. The `# ai-sync-generated` first-line marker identifies generated files — any TOML without it is treated as user-owned and preserved. User-authored commands you add directly under `.gemini/commands/` (outside `run/`) are left untouched.

Run `/commands list` to view all available commands, or `/commands reload` to pick up file changes without restarting. Project commands take precedence over identically-named user commands.

Docs: https://geminicli.com/docs/cli/custom-commands/

### Codex

Project-scoped MCP config via TOML (trusted projects only):

- `~/.codex/config.toml` — global (user-level) MCP servers
- `.codex/config.toml` — project-scoped MCP servers

Config format:
```toml
[mcp_servers.server-name]
command = "npx"
args = ["-y", "@foo/bar"]
env = { API_KEY = "value" }
```

The sync script generates `.codex/config.toml` from `.ai/mcp-servers.json`. It will not overwrite a manually edited file (ownership detected via `# ai-sync-generated` marker at the top).

Docs: https://developers.openai.com/codex/mcp

### Gemini CLI

MCP servers live under the `mcpServers` key of Gemini's settings file:

- `~/.gemini/settings.json` — global (user-level)
- `.gemini/settings.json` — project-scoped

Config format (same shape as `.mcp.json`, with extra optional fields):
```json
{
  "mcpServers": {
    "server-name": {
      "command": "npx",
      "args": ["-y", "@foo/bar"],
      "env": { "API_KEY": "$MY_API_TOKEN" },
      "timeout": 30000,
      "trust": false,
      "includeTools": ["tool-a"],
      "excludeTools": ["tool-b"]
    }
  }
}
```

Transports: `command`/`args` (stdio), `url` (SSE), or `httpUrl` (streamable HTTP) — one is required. `trust: true` bypasses tool-call confirmations for that server. `excludeTools` wins over `includeTools`. Env values support `$VAR_NAME` / `${VAR_NAME}` expansion.

The sync script **merges** the `mcpServers` from `.ai/mcp-servers.json` into `.gemini/settings.json`: other settings keys and user-added servers with different names are preserved; same-named servers are overwritten by the `.ai/` source.

Inside a session, `/mcp` lists each connected server's Tools, Prompts, and Resources. Resources can be referenced with `@server://resource/path` syntax.

Docs: https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/mcp-server.md
