# Blueprint: Agnostic Cross-AI Workspace & Context Harness

## 1. Architectural Strategy

Modern AI engineering tools change too quickly to lock project rules into tool-specific hidden directories (like `.claude`, `.cursor`, or `.github`). This architecture establishes a **vendor-agnostic workspace configuration** (`.ai/` and `docs/`) as the single source of truth.

Tool-specific configurations are treated as transient compilation targets. A native, zero-dependency Node.js script (`.ai/scripts/sync.js`) dynamically links or copies these files to target locations, allowing human developers to work with a clean, semantic file layout. Node is the engine specifically because it is identical across macOS and Windows.

Key consolidation decisions:

- **One agent brief.** `.ai/agents.md` is the canonical instructions file, linked to root `AGENTS.md` (the de-facto cross-tool standard read by Codex CLI, Cursor, Copilot coding agent, Amp, Jules, and others), `CLAUDE.md` (Claude Code), `GEMINI.md` (Gemini CLI), and `.github/copilot-instructions.md` (VS Code Copilot).
- **One MCP config.** Root `.mcp.json` is read natively by both Claude Code and Copilot/VS Code — good enough; no per-tool MCP generation.
- **One skills folder.** Flat `.ai/skills/*.md` files are compiled into the `<name>/SKILL.md` folder wrappers required by both Claude Code (`.claude/skills/`) and VS Code Copilot (`.github/skills/`).
- **One prompts folder.** Flat `.ai/prompts/*.md` files become slash commands in both harnesses: `.github/prompts/<name>.prompt.md` (Copilot `/name`) and `.claude/commands/<name>.md` (Claude Code `/name`). Authoring note: stick to portable frontmatter (`description`) and argument placeholders both tools understand (Claude uses `$ARGUMENTS`/`$1`, Copilot uses `${input}` — for shared prompts, prefer plain prose like "the user will specify the target" over placeholders).
- **No tool-config TOML.** No current harness reads a shared `config.toml`; metadata lives in the markdown files themselves (frontmatter).

### Authoring Convention: Root-Relative Links

All cross-references inside `.ai/` source files (links to skills, docs, or other markdown) **must be written as root-relative paths**, e.g.:

```markdown
See [docs/systemArchitecture.md](docs/systemArchitecture.md) and
[.github/skills/code-reviewer/SKILL.md](.github/skills/code-reviewer/SKILL.md).
```

Rationale: symlinks resolve relative links from the *link's* location, not the source file's. Since the canonical render targets are at the repo root (`AGENTS.md`) and inside `.github/`/`.claude/`, root-relative links work everywhere the files are consumed. The only place they appear broken is when navigating inside the `.ai/` source file itself in an editor — an acceptable trade-off. In the rare copy-fallback case (locked-down Windows), links break identically in both targets and remain findable by agents.

> **Trade-off note:** because root `AGENTS.md`/`CLAUDE.md` are generated and gitignored, a fresh clone (or the GitHub web UI) won't show them until the sync runs. If GitHub rendering matters for a given repo, commit the generated root files instead and remove them from `.gitignore` — the sync engine preserves non-symlink files it didn't create.

## 2. Git Configuration

### `.gitignore`

Ignore only the *generated* artifacts — explicitly, never wholesale. In particular, do **not** ignore all of `.claude/` (shared `settings.json`, hooks, and commands belong in version control) or all of `.github/` (workflows, tracked instructions).

```text
# =========================================================================
# Cross-AI Tooling — auto-generated by .ai/scripts/sync.js
# =========================================================================
/AGENTS.md
/CLAUDE.md
/GEMINI.md
/.mcp.json
/.github/copilot-instructions.md
/.github/prompts/
/.github/skills/
/.claude/commands/
/.claude/skills/
/.ai/.sync-manifest.json

# Local-only AI settings
.claude/settings.local.json
```

### `.gitattributes`

Git hooks must keep LF line endings on every platform (Git for Windows runs them with its bundled `sh.exe`):

```text
.githooks/* text eol=lf
```

## 3. Sync Engine (`.ai/scripts/sync.js`)

The sync engine lives at `.ai/scripts/sync.js`. See that file for the full implementation.

**Behavior summary:**

- Creates target directories if missing
- Links (symlink) each source to its harness-specific destination
- On Windows without Developer Mode/Admin: falls back to copy with a hash manifest (`.ai/.sync-manifest.json`) for drift detection
- **Copy-fallback header injection:** when copying `.md` files (no symlink permission), prepends `<!-- AUTO-GENERATED by .ai/scripts/sync.js — edit the source at <path> instead -->` so editors of generated copies are warned
- **Guardrail:** never clobbers human-created files — only replaces symlinks and copies whose hash matches the manifest
- Cleans stale symlinks for skills/prompts that no longer exist in `.ai/`
- Idempotent: safe to run repeatedly from any trigger

**Watch mode (`--watch`):**

```bash
node .ai/scripts/sync.js --watch
```

Uses Node's built-in `fs.watch` with `{ recursive: true }` on `.ai/` — zero dependencies, works on both macOS and Windows. Debounces at 300ms and re-runs sync on any source file change. Useful during active skill/prompt authoring.

## 4. Invocation (Cross-Platform)

The sync script is idempotent, so every trigger below can coexist. All four paths work identically on macOS and Windows.

### a) Manual

```bash
node .ai/scripts/sync.js
```

### b) npm alias (`package.json`) — optional

If the project already has a `package.json`, add these scripts to it. If not, a minimal one is harmless but not required — the manual `node` command works fine:

```json
{
  "private": true,
  "scripts": {
    "ai-sync": "node .ai/scripts/sync.js",
    "ai-watch": "node .ai/scripts/sync.js --watch",
    "postinstall": "node .ai/scripts/sync.js"
  }
}
```

`postinstall` makes sync automatic on `npm install`. `ai-watch` is convenient during authoring sessions.

### c) Git hooks (covers CLI users)

Tracked hooks in `.githooks/` — Git for Windows bundles `sh.exe`, so plain `sh` hooks run identically everywhere. Both `post-merge` and `post-checkout` contain:

```sh
#!/bin/sh
node .ai/scripts/sync.js
```

One-time setup per clone (document in `.ai/agents.md` / README):

```bash
git config core.hooksPath .githooks
```

(The `.gitattributes` rule from §2 guarantees LF endings so the hooks run on Windows.)

### d) VS Code task (covers editor users)

`.vscode/tasks.json` — runs on workspace open after a one-time "Allow Automatic Tasks" approval:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "ai-sync",
      "type": "shell",
      "command": "node .ai/scripts/sync.js",
      "runOptions": { "runOn": "folderOpen" },
      "presentation": { "reveal": "silent" }
    }
  ]
}
```

## 5. Developer Optimization & Coexistence Rules

1. **Global/Personal Machine Overrides:** Configure machine-specific preferences (API credentials, default models) in global user paths (`~/.claude/CLAUDE.md`, `~/.claude/settings.json`, VS Code user settings) — never inside the repository.
2. **Local-only experiments:** A teammate can hand-create a file at any generated destination (e.g. a personal `.claude/skills/personal-rule/SKILL.md`). The guardrail mechanism preserves it: the sync engine only replaces symlinks and copies whose hash matches its manifest; any other physical file is treated as a local override and left untouched.
3. **Tracked Claude settings:** Keep shared `.claude/settings.json` (permissions, hooks, commands) in version control; only `.claude/settings.local.json` is ignored.
4. **Context hygiene:** Maintain consistent AI-ignore rules per tool where needed (e.g. `.cursorignore`, `.geminiignore`) for heavyweight noise like backups, caches, and binary project files. Pair with a tracked `.editorconfig` so every agent's edits follow indentation/encoding rules without burning prompt tokens on it.
5. **Memory conventions:** `docs/activeContext.md` is the cross-tool session memory. Tools with native memory systems (e.g. Copilot's repo memory) should be instructed in `.ai/agents.md` to mirror durable findings into it.

## 6. Implementation Strategies

### Strategy A: Project Template Repository (For New Projects)
1. Commit this structure into a new workspace.
2. Set the workspace as a **Template repository** via GitHub repository settings.
3. Teammates click **Use this template**, then run `git config core.hooksPath .githooks` and `node .ai/scripts/sync.js` (or `npm install`) to bind the environment.

### Strategy B: Retrofit Existing Projects
1. Copy `.ai/` (with `scripts/sync.js`), `.githooks/`, and the `.vscode/tasks.json` task into the existing repo.
2. Move existing instructions content (`CLAUDE.md`, `AGENTS.md`, `copilot-instructions.md`) into `.ai/agents.md`, converting internal links to root-relative paths; move existing skills into flat `.ai/skills/*.md` files.
3. Delete the originals, add the §2 `.gitignore`/`.gitattributes` rules, and run `node .ai/scripts/sync.js` — the originals are regenerated as links.
4. Optionally maintain `.ai/` as a **git submodule or subtree** shared across an ecosystem of projects, so prompt/skill improvements propagate everywhere with a single `git submodule update --remote`. Keep project-specific content (`agents.md`, `docs/`) outside the shared module.
